# Domain and tool adapters

**Draft v0.1 — reference only.** No adapter is installed or required. Keep essential state accessible without the original harness.

| Domain | Boundaries and evidence | Whole-work responsibility |
|---|---|---|
| Software | Interfaces, state ownership, dependencies; real inputs, reference behavior and existing CI | Assemble and exercise the normal user flow; local passes do not establish global correctness |
| Writing | Purpose, audience, chapter/section responsibilities, continuity and source notes | One editor preserves argument, voice, chronology and coherence; avoid prescribing every sentence |
| Research | Questions, source versions, methods, claim/evidence links and uncertainty | One synthesis owner reconciles contradictions and checks conclusions against originals; unknowns remain distinct from facts |

Native harness features may implement assignments, worktrees, messages, review or checkpoints. Use them when available and useful. Tool-specific session IDs are supplementary pointers, not the only record of unfinished work.

For Git projects, isolated worktrees help separate file edits; shared services and non-Git resources still need explicit ownership. For documents, separate owned drafts can serve the same purpose, followed by controlled assembly. Small projects can use one worker and one record throughout.

Preserve the project's required checks and owner rules. This kit introduces no fabricated fixtures, mock runs, new approval hierarchy or mandatory test-count target.
