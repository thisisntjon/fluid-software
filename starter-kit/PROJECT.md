# Project fields

**Draft v0.1.** Put these in the existing project entry; do not create a competing board. Include only fields needed to guide work. Existing project authority governs.

## Essential

- **Outcome / consumer:** What useful result is being built, for whom?
- **Acceptance:** What actual use or observation establishes success? Who can accept it?
- **Scope / authority:** Included work, exclusions, existing permissions, budget and required checks.
- **Current reality:** Working artifacts, known failures, consequential sources with version/date, and inspected reuse decisions.
- **Accepted state / continuation:** Exact last accepted artifact and version with evidence pointer, or explicitly “none accepted yet”; incomplete work and the next continuation action.
- **Responsibility map:** How modules or sections contribute to the whole. Link deeper units only as needed.
- **Dependency map:** What each ready unit needs first; identify shared decisions and mutable resources. The hierarchy is not the schedule.
- **Frame for substantial work:** Links to actual module/section homes, native contracts, usable foundations and local entrypoints; clearly distinguish implemented, accepted, deferred and unresolved areas.
- **Current action:** Owner, next useful unit, blocker if any, and links to its output/evidence.

## Add when risk warrants

- **Shared contracts:** Authoritative location, version, owner and affected consumers.
- **Uncertainty:** Claim, evidence, confidence, practical consequence and what would change the decision.
- **Assembly:** Accountable owner, integration order and required product-level observation.
- **Capacity:** Available workers and current assembly/review bottleneck; adjust assignments accordingly.
- **Area ownership:** For larger projects, delegated internal decisions and local assembly, public obligations, relevant neighbors and current accepted versions. Keep this in each area's existing home and link it here; root need not ingest all local history.
- **Recovery procedure:** How to restore the accepted state when needed, including limits for external actions that file rollback cannot reverse.

Update this entry when scope, evidence or dependencies change. Keep detailed logs elsewhere and link them. Do not mark the whole complete merely because all worker cards are closed.
